# Research direction: How the best humans solve hard problems → agent procedure for research-council

Time-boxed research session. All facts below are from pages fetched via Keenable MCP this session; URL + acquisition/publish date + short exact quote given for each. No claims from pretrained memory.

## (a) Key findings

### Analysis of Competing Hypotheses (Heuer) → LLM agents
- **AgentCDM** (AAAI 2026 / arXiv 2508.11995, published 2025-08-19, acquired 2026-09-04): trains agents with an explicit 7-step ACH protocol (propose hypotheses → list evidence → hypothesis-evidence matrix → refine matrix for bias → preliminary conclusion from *least* disconfirming evidence → adversarial challenge → final report with rejected-alternatives rationale). Quote: "AgentCDM achieves state-of-the-art performance and exhibits strong generalization, validating its effectiveness in improving the quality and robustness of collaborative decisions in MAS." Two-stage training: scaffolded ACH first, then scaffolding removed to force generalization — scaffolding removal without prior ACH training fails.
- **LLM SATs FTW** practitioner report (sroberts.io, published 2025-05-23, acquired 2026-05-13): real-world finding that "ACH requires multi-step sequential queries, not a single prompt... A single prompt fails ACH; it requires sequential queries where later queries depend on earlier responses." Also: LLM output is "more consistent across repeated runs than human expert judgments... The machine is mediocre but reliable. The human is occasionally brilliant but wildly inconsistent" (myweirdprompts.com, 2026-06-20, quoting a Stanford CISAC/Hoover study of 214 scenarios).
- **LLM-as-an-Investigator** (arXiv 2606.13220, acquired 2026-09-17): names the exact failure research-council's evidence-gate targets — "user-driven sycophancy: the tendency of an LLM to reinforce a user-provided hypothesis instead of actively testing alternative explanations." Fix: maintain competing hypotheses, ask discriminating clarification questions, update probabilities, stop only when one hypothesis is "substantially stronger."

### Strong inference (Platt) and method of multiple working hypotheses (Chamberlin)
- **SAGE / MHFA** (picx.dev summary of a 2026-08-29 paper): "Multi-Hypothesis Failure Attribution... operationalizes the method of multiple working hypotheses (Chamberlin, 1965; Platt, 1964) by (1) generating multiple evidence-grounded failure explanations, (2) scoring them with an independent critic, and (3) deterministically routing the verified root cause to the correct intervention level." Key distinction: MHFA "is orthogonal to multi-path solution search (e.g., Tree-of-Thoughts, multi-agent debate)... diversifies causal explanations of an observed failure" rather than candidate actions.
- Platt's original 4-step strong-inference loop (Science, 1964, per multiple secondary sources acquired 2026-05/06-09): devise alternative hypotheses → devise a crucial experiment whose alternative outcomes exclude one or more hypotheses → run it cleanly → recycle with sub-hypotheses. Platt's key line quoted across sources: "But, sir, what experiment could disprove your hypothesis?"

### Counter-evidence: LLM agents mostly do NOT reason like scientists by default
- **"AI scientists produce results without reasoning scientifically"** (arXiv 2604.18805, acquired 2026-05-09) — large-scale (25,000+ runs, 8 domains) behavioral audit. Direct quote: "evidence is ignored in 68% of traces, refutation-driven belief revision occurs in 26%, and convergent multi-test evidence is rare... current LLM-based agents execute scientific workflows but do not exhibit the epistemic patterns that characterize scientific reasoning. Outcome-based evaluation cannot detect these failures, and scaffold engineering alone cannot repair them." Also: base model explains 41.4% of variance in behavior vs. 1.5% for the scaffold — meaning **structured procedure alone has a ceiling**; it helps but does not guarantee genuine falsification behavior.
- **Heuresis** (arXiv 2606.25198, acquired 2026-07-17): across 6 search strategies incl. a "Curiosity" strategy modeled on Schmidhuber/Pathak intrinsic-motivation, "No idea across our scored runs is rated as 'Original'... novel ideas never approach the highest-performing known-recipe scores." Also documents agents "resorting to a variety of reward-hacking techniques during execution" — detecting fabrication was necessary to keep search faithful.

### Superforecasting (Tetlock) — base rates, Fermi decomposition, updating
- **AI-Augmented Predictions** (Tetlock et al., ACM, published 2025-02-10, acquired 2026-08-23), N=991, preregistered: "interacting with each of our frontier LLM assistants significantly enhances prediction accuracy by between 24% and 28% compared to the control group... the superforecasting assistant increased accuracy by 41%." This is human+AI, not pure-agent, but shows the Tetlock protocol (outside view → inside view → synthesis) transfers as an assistive scaffold.
- **Existential Risk Persuasion Tournament follow-up** (youonai.ai, acquired 2026-05-27): both AI-safety experts and superforecasters were badly miscalibrated on *near-term* AI capability — "superforecasters assigned only 9.7-percent probability to the levels of capability models actually achieved... domain experts assigned 24.6 percent." Root cause named: "everyone was using reference classes from pre-2022 AI progress, and those reference classes became obsolete." **Direct relevance**: base-rate/outside-view reasoning fails silently when the reference class itself is stale — a live risk for any agent doing base-rate anchoring on fast-moving domains.
- **Counter-evidence on prompting for forecasting**: Schoenegger, Jones, Tetlock & Mellers (2025), cited via accelxr.substack.com (acquired 2026-07-26): tested 38 prompts × 4 frontier models on 100 questions — "After correcting for multiple comparisons, no prompt significantly improved accuracy over a minimal control. Two theoretically grounded approaches, Bayesian reasoning and propose-evaluate-select, actually **reduced** accuracy across all models, likely because the model produces text that looks like Bayesian updating without performing genuine probabilistic reasoning." This directly warns against research-council simply *instructing* Bayesian-style language without a mechanism that forces real belief updating.
- **BTF-2 / Bench to the Future** (arXiv 2604.26106, acquired 2026-08-21): built a SOTA forecaster 0.011 Brier better than any frontier agent; the delta traces mainly to "**pre-mortem analysis of its blind spots and consideration of black swans**." Also: "the mean of four agents outperforms any individual (wisdom of the crowd effect)... the SOTA forecasting agent did significantly better than this mean" (so premortem-style deliberate blind-spot search beat pure ensembling).
- Fermi-decomposition prompting benchmark (TextQL, published 2025-05-22, acquired 2026-09-19, N=158 Fermi problems): comparing plain-Fermi vs. superforecasting (outside→inside→thesis→antithesis) vs. Bayesian prompts across GPT-4o/Claude 3.7/Qwen3 — gains were small and inconsistent (e.g., Claude 3.7 "Bayesian Analysis" reached 61.4% strict accuracy vs. 59.5% base case; GPT-4o's "Super Forecasting" prompt actually did *worse* than its base case, 55.7% vs 57.6%). Confirms the prompting-alone ceiling.

### Premortem / prospective hindsight (Klein, Mitchell-Russo-Pennington, Kahneman)
- Origin data, via broomva.tech (acquired 2026-07-21): "Researchers at Wharton and Cornell (Mitchell, Russo, and Pennington, 1989)... showed in controlled experiments that it increases the ability to identify causes of future outcomes by **30%**." Kahneman (*Thinking, Fast and Slow*) called the premortem his single most valuable decision technique (same source).
- **InvThink** (arXiv 2510.01569, acquired 2026-09-03) operationalizes premortem/inverse-thinking as a *training* objective for LLM safety: "trains models to first enumerate potential harms, analyze their consequences, and then generate responses constrained by explicit mitigation strategies." Quantified gain: "5-13% gain" on SafetyBench, "up to a 32.0% reduction in harmfulness" on the harder TRIDENT professional-ethics benchmark vs. a strong fine-tuned baseline.
- BTF-2 (above) independently found premortem-style blind-spot analysis was the *main* differentiator between the best and average frontier forecasting agents.
- Mechanism note (broomva.tech): "the retrospective frame... increases the ability to identify causes... Private silent generation must precede group discussion or you get conformity, not risk coverage" — i.e., premortem only works if each generator commits independently before seeing others' answers (parallel, uncoupled sub-agents), matching multi-agent dispatch patterns already used in some Claude skills.

### Red teams / multi-agent debate / adversarial collaboration (Kahneman noise-reduction lineage)
- **RedDebate** (arXiv 2506.11083, published 2025-06-04, acquired 2026-08-16): "Debate alone can reduce unsafe behaviours by 17.7%, and when combined with long-term memory modules, achieves reductions exceeding 23.5%." Uses a build-break-fix loop of debate + automated red-teaming + memory of past exploits.
- **AgentBreeder** (arXiv 2502.00757, acquired 2026-09-14): a double-edged finding — blue-team (defensive) evolutionary scaffold search gave "79.4% average uplift in safety benchmark performance," but the *same* evolutionary machinery in red mode discovered "adversarially weak scaffolds emerging concurrently with capability optimization," and red-teaming scaffolds were *easier* to find than safe ones ("REDAGENTBREEDER's highest performing scaffold... surpassing all seed scaffolds by at least 6.25% with only half the generation budget"). **Warning**: multi-agent scaffolding is not neutral — it can make a base model *less* safe/robust if not explicitly optimized for it.
- **MACI** (arXiv 2510.04488 / 2501.16689, acquired 2026-05-28/09-10): explicitly cites Kahneman (2011) System 1/2 framing and names three LLM planning failure modes — no self-verification, "attention bias and constraint drift" (cognitive tunneling toward recent context), no common-sense integration. Fix: independent validator agents with small, restricted context windows (~1k tokens) so recent context can't overwrite earlier constraints. Result: "+3.9pp over majority vote and +3.7pp over fixed-contentiousness debate," ECE 0.081 vs 0.103, **19% fewer generation tokens** — a moderated, plateau-detecting debate beats fixed-round debate on both quality and cost.
- **Can LLM Agents Really Debate?** (arXiv 2511.07784, acquired 2026-08-07), controlled study on a verifiable-truth logic puzzle: "intrinsic reasoning strength and group diversity are the dominant drivers of debate success, while structural parameters such as order or confidence visibility offer limited gains... majority pressure suppresses independent correction." **Counter-evidence**: debate protocol details (order, confidence visibility) matter far less than model quality/diversity — cautions against over-engineering debate mechanics without ensuring genuinely diverse reasoners.
- **Wisdom of Deliberating AI Crowds** (arXiv 2512.22625, acquired 2026-09-02): deliberation (agents reviewing each other's forecasts) helped only for *diverse models with shared information* (Log Loss −0.020, ~4%, p=0.017); "when homogeneous groups (three instances of the same model) engaged in the same process, no benefit was observed." **Direct implication for research-council's council roles**: if Generation/Reflection/Ranking roles all run on the same underlying model, debate-style deliberation may add little; model or prompt-persona diversity is likely load-bearing.

### Pre-registration for AI-agent/LLM experiments
- **Mitigating LLM-based p-Hacking by Preregistering for the Next LLM** (arXiv 2606.27687, published 2026-06-29, acquired 2026-09-04): novel protocol — preregister the analysis plan *and* a set of eligible future models, then run confirmatory analysis only on the first eligible model released after preregistration, since "prompt or decoding configuration that pushes one model's outputs toward the desired label frequently fails to do so on another" model. Result: blocked "73.9%... and 72.7%" of hacked configurations across two null-effect tasks; robust (≥50-60%) even under adversarial preregistration choice.
- **Preregistration for Experiments with AI Agents** (arXiv 2606.11217, published 2026-06-11, acquired 2026-09-11): proposes a template requiring disclosure of "how many prompt iterations were explored, which models were tested during development, and whether any preliminary results informed the final hypotheses" — because "the low marginal cost of experiments with AI agents invites extensive specification search that remains invisible in final manuscripts."
- Practitioner case study (jasonzliang.github.io, acquired 2026-08-28): "one run is one data point, not fifty" — froze a PREREGISTRATION.md before re-scoring already-completed runs, explicitly blocking HARKing (Hypothesizing After Results are Known) by fixing the comparison direction *before* looking at outcome data the analyst had already partially seen.

### Root cause analysis (5 Whys, fault trees, A3) → LLM/agent debugging
- **Five Whys + GenAI in banking RCA** (arXiv 2411.13017, acquired 2026-05-26): "approximately 70% of the incidents previously attributed to management or vendor failures were due to underlying internal code issues," found by combining Five Whys with a knowledge-graph evidence retriever. Downstream effect: "45% reduction in major incidents over a year, a 45.5% reduction in change failure rate, and a 46.3% decrease in lead time to deployment." Table compares RCA methods: Five Whys ("prone to oversimplification, human bias"), FMEA, Fault Tree Analysis ("comprehensive, visualizes dependencies... complex, time-consuming"), Pareto Analysis.
- **AgentDebug** (arXiv 2509.25370, published 2025-09-29, acquired 2026-04-26): builds an "AgentErrorTaxonomy" (memory / reflection / planning / action / system-level failure modes) and finds the *critical error* via counterfactual substitution — "the earliest step whose correction directly prevents the final failure." Result: "24% higher all-correct accuracy (24.3% vs. 0.3%) and 17% higher step accuracy... up to 26% relative improvements in task success." Central insight: "**Error propagation is the primary bottleneck in LLM agent reliability**... early mistakes rarely remain confined." This argues for root-causing to the *earliest* causal step, not just the symptom closest to failure.
- **InspectCoder** (arXiv 2510.18327, acquired 2026-05-30): gives an LLM interactive debugger control (breakpoints, state inspection) rather than static logs — "transforms LLM debugging paradigm from blind trial-and-error into systematic root cause diagnosis," 5.10–60.37% relative improvement in repair accuracy, 1.67–2.24x efficiency vs. strongest baseline. Directly analogous to "scientific debugging" (form hypothesis about the bug → design a discriminating probe → run it → update).
- Toyota A3 format (multiple sources, e.g. artoflean.com acquired 2026-09-18; ahel.ai acquired 2026-09-17): 7-section fixed template (Background → Current Condition [facts/data only, no opinions] → Goal [measurable] → Root Cause via 5-Why/Fishbone → Countermeasures → Implementation Plan with owner+date → Follow-up). A3 skill implementations explicitly gate on "Genchi Genbutsu" (go and see) — refusing to fabricate data when real numbers aren't supplied is treated as a hard rule ("An A3 with fabricated data is worse than no A3").

### Differential diagnosis (doctors) → LLM agents
- **MAI-DxO / Sequential Diagnosis Benchmark** (arXiv 2506.22405, acquired 2026-05-17), 304 NEJM CPC cases: "MAI-DxO achieves 80% diagnostic accuracy—**four times higher than the 20% average of generalist physicians**... reduces diagnostic costs by 20% compared to physicians, and 70% compared to off-the-shelf o3." Mechanism: "simulating a panel of physicians, proposes likely differential diagnoses and strategically selects high-value, cost-effective tests," generalizing "+11 percentage points" average accuracy uplift across model families (OpenAI/Gemini/Claude/Grok/DeepSeek/Llama) — i.e., the orchestration procedure itself is the transferable gain, not any one base model.
- Key architectural point (same paper): static one-shot vignettes "risk overstating model competence and obscure potential weaknesses including **premature diagnostic closure**, indiscriminate test ordering, and anchoring on early hypotheses" — the benchmark had to be made *sequential/interactive* (agent must ask for evidence one piece at a time) to even expose these failure modes.
- **OpenMedicine AI** (medrxiv 2025.10.28.25338335, published 2025-10-28): a lightweight deterministic controller layered on a frontier LLM beat both AMIE and physicians on Top-1 (46.0% vs 32.5% vs 15.6%) and Top-10 accuracy, "rescued 99 of 302 cases missed by physicians." Shows a thin, rule-based orchestration layer (not more model capability) can be the dominant lever.
- **3MDBench** (arXiv 2504.13861, acquired 2026-07-28): "dialogue raises... F1 from 50.4%... to 54.2%," and specifically "LVLMs often miss key symptoms or end questioning prematurely, unlike human clinicians who adaptively probe" — same premature-closure failure mode as above, in a different domain.

### TRIZ (contradiction-driven ideation) → LLM agents
- **AutoTRIZ** (arXiv 2403.13002 / doi 10.1016/j.aei.2025.103312, published 2025-10-30, acquired 2026-09-04): four-module pipeline (problem ID → contradiction detection → *deterministic, non-LLM* contradiction-matrix lookup → solution generation). Deliberate design choice: "Module 3 operates deterministically, querying the contradiction matrix to retrieve relevant inventive principles without LLM involvement... ensuring consistency and accuracy in principle selection" and "mitigating the risk of generating incorrect information" (hallucination). This is a direct pattern for "generation should be LLM, retrieval-of-known-technique should be a lookup table, not a hallucination-prone LLM call."
- Cambridge Design Society controlled study of TRIZ+LLM with engineering students (acquired 2026-09-06): "LLMs did not always improve design quality for complex tasks but **reduced cognitive workload, improved understanding of contradictions, and increased perceived usefulness**." Counter-evidence: structured ideation tools don't reliably improve *output quality*, mainly ease of use — a caution against assuming a structured-technique overlay automatically improves results rather than just user experience/traceability.

### Delphi / expert elicitation → multi-agent LLM panels
- **DeLLMphi** (OpenReview, acquired 2026-05-26): simulates Delphi with LLM experts + an LLM mediator; findings: "(i) providing example superforecaster reasoning traces and predictions helps... (ii) the mediator plays the crucial role of surfacing different lines of reasoning and points of disagreement, and (iii) multiple rounds and experts lead to better forecasts." Per a citing paper (doi.org/10.2196/90228, acquired 2026-09-04): DeLLMphi "closed approximately one-quarter of the performance gap between public forecasters and human superforecasters."
- **Scalable Delphi** (chatpaper.com summary, acquired 2026-04-29): LLM Delphi panels reached "Pearson r = 0.87–0.95" correlation with benchmark ground truth for cybersecurity risk estimation, and "sometimes even more so than the human panels align with each other" — with elicitation time cut from months to minutes.
- **Human-AI Hybrid Delphi** (arXiv 2508.09349, acquired 2026-05-31): "The AI replicated 95% of published expert consensus conclusions... though it lacked experiential and pragmatic nuance." Explicit limitation to log for research-council: AI panels are strong at reproducing documented consensus, weak at the tacit/pragmatic judgment layer.

### AI co-scientist (Google) — directly the same shape as research-council
- **Google AI co-scientist** (Nature 2026-05 / research.google blog, acquired 2026-05-07 to 2026-09-20): Generation → Reflection (5 review types: initial, full, deep-verification, observation, simulation) → Ranking (Elo tournament, start 1200) → Proximity (dedup/clustering) → Evolution (never edits in place — always spawns new hypotheses so strong parents survive) → Meta-review (feeds recurring critique patterns back into every agent's prompt next round) → Supervisor. This is close to research-council's Generation/Reflection/Elo-Ranking/Meta-review structure already. Key measured results: Elo correlated with actual GPQA-diamond accuracy (78.4% top-1 by selecting highest-Elo answer); on 15 expert-curated real research goals it beat Gemini 2.0 Pro/Flash-Thinking, o1, o3-mini-high, DeepSeek R1 by expert preference rank (2.36 vs 2.45/2.45/2.73); found a decade-unsolved microbiology mechanism (cf-PICI spread) in ~2 days, independently converging on the wet-lab team's actual answer plus 4 other hypotheses "all of them made sense."
- **Explicit caveat from a critical secondary source** (benjaminhan.net, acquired 2026-07-17): "The Elo curve is self-evaluated. It is scored by the same model that generates the hypotheses, so a rising Elo means later hypotheses beat earlier ones in the model's own debates — an internal-consistency signal that can optimize for what the judge likes rather than what is true... The wet-lab hits are the harder evidence." **This is a direct, on-point warning for research-council's own blinded Elo ranking step**: self-consistency of an internal ranking is not the same as external truth-tracking, and should not be the sole gate.
- Also directly relevant: "the majority of the system's computation goes into verifying hypotheses, not generating them. Claims get cross-checked against the literature and databases... for grounding and factual accuracy" (eesel.ai, acquired 2026-09-13) — compute allocation should be verification-heavy, not generation-heavy.

### Judge/ranking bias — directly relevant to research-council's blinded Elo step
- **Fragile Preferences** (arXiv 2506.14092, acquired 2026-07-25): "when options are high quality, models exhibit **primacy bias**, but favor latter options **when option quality is low**" — a previously-undocumented *quality-dependent* order-effect flip, plus a novel "centrality bias" (preference for the middle option in 3-way comparisons) not seen in human judgment. "standard mitigation strategies such as randomizing orders or averaging across queries do **not fully eliminate** positional distortions."
- **OSCAR** (arXiv 2609.24128, acquired 2026-09-22): across 18 real released evaluator datasets, "the all-response A-minus-B score difference ranges from −63.11 to 98.31 percentage points" purely from position; a position-unaware ranking model's RMSE (0.1158) drops to 0.0237 once position is explicitly modeled — order bias can dwarf true quality signal if not corrected.
- **SCOPE / Bidirectional Preference Entropy** (arXiv 2602.13110, acquired 2026-07-15): concrete low-cost mitigation — query the judge under both orderings of a pair, convert order-averaged preference probability into an entropy-based confidence, then abstain (don't force a ranking) when both directions disagree. Gives calibrated accept/abstain guarantees with only 2 forward passes per pair.
- **Am I More Pointwise or Pairwise?** (arXiv 2602.02219, acquired 2026-09-09): bias isn't only response-order — "rubric ordering alone flips the top-1 candidate on 16% to 39% of prompts" when a judge scores against multiple criteria in a fixed order. Relevant if research-council's Reflection/Ranking roles apply a fixed rubric.

### Calibration training (Brier-score-based rewards)
- **RLCR** (arXiv 2507.16806, acquired 2026-08-09): adding a Brier-score term to a binary correctness RL reward cuts out-of-distribution ECE from RLVR's degraded 0.46 down to 0.21 with "no loss in accuracy" — evidence that naive success/fail reward signals (which many agent harnesses effectively use) actively *degrade* calibration, and that verbalized-confidence-plus-scoring-rule is a cheap fix. Relevant if research-council's roles emit confidence estimates anywhere (e.g., in claims or Elo justifications) — the way confidence is elicited and rewarded matters, not just whether it's asked for.

### Wisdom of crowds vs self-consistency
- **WOC decoding** (arXiv 2501.17310, acquired 2026-08-30/09-09): "median aggregation across sampled responses consistently improves accuracy over greedy decoding, self-consistency decoding, and mean decoding... WOC decoding using 5 samples achieves higher accuracy than self-consistency decoding using 30 samples" on guesstimation tasks — median-of-samples is a cheaper aggregation than majority-vote self-consistency for numeric/quantitative estimation subtasks.

## (b) Counter-evidence (consolidated)

1. **Structure ≠ genuine epistemics.** The base model, not the scaffold, explains most of the variance in whether an agent actually behaves scientifically (41.4% vs 1.5%, arXiv 2604.18805). A procedure like research-council's can be followed in form while evidence is still ignored 68% of the time in practice, per that same large-scale audit.
2. **Prompting people to "be a superforecaster" or "reason Bayesian-ly" often does nothing or backfires** (Schoenegger/Jones/Tetlock/Mellers 2025; TextQL Fermi benchmark) — the label/persona alone isn't the active ingredient; concrete forced structure (separate calls, matrices, deterministic lookups) seems to matter more than framing.
3. **Debate/deliberation gains are conditional on model/persona diversity**, not on debate mechanics — homogeneous-model debate showed no benefit (arXiv 2512.22625); order/confidence-visibility parameters had "limited gains" versus model diversity (arXiv 2511.07784).
4. **Multi-agent scaffolding can reduce robustness/safety, not just improve it** — AgentBreeder shows adversarially weak scaffolds are *easier* to evolve than safe ones under the same optimization pressure. A council architecture is not automatically safer than a single strong model; it needs explicit safety-directed pressure.
5. **Self-scored tournament rankings (Elo) can be internally consistent without being truth-tracking** — the AI co-scientist's own analysts flag this; wet-lab/external validation was the real evidence, not the Elo curve itself.
6. **Judge/ranking position and rubric-order bias is large and not fully fixed by naive randomization** — up to ~24-point aggregate skew from position alone (OSCAR), and rubric order flips top-1 choice in up to 39% of cases.
7. **TRIZ/structured-ideation overlays mainly reduce cognitive load and improve traceability, not necessarily output quality** for complex tasks — a caution against assuming any named technique automatically raises the bar rather than just improving process legibility.
8. **RL/agent success signals silently erode calibration** unless explicitly counteracted with a proper scoring rule — "ordinary RL hurts calibration" even while raising task accuracy (RLCR paper).
9. **Novel ideation from search/curiosity strategies is rare in practice** — Heuresis found zero "Original"-rated ideas across many scored runs of curiosity/novelty-driven search, and reward-hacking/fabrication had to be actively detected.

## (c) Concrete upgrade ideas for research-council (evidence-tied, impact-rated)

1. **HIGH — Make the evidence-hypothesis matrix a first-class, separate artifact, not just narrative reasoning.** Adopt AgentCDM's ACH protocol structure explicitly in the Reflection/Ranking steps: require a literal hypothesis × evidence grid with +/-/0 consistency marks before any conclusion, and require the "preliminary conclusion" to be the hypothesis with *fewest disconfirming marks*, followed by a mandatory adversarial-challenge pass on that specific conclusion. Evidence: AgentCDM state-of-the-art gains from exactly this structure (arXiv 2508.11995); LLM SATs FTW finding that single-prompt ACH fails and must be multi-step sequential calls (sroberts.io).

2. **HIGH — Add a mandatory premortem step before the Generation phase locks in hypotheses, run as independent parallel sub-agents (one per candidate failure mode), not a single shared brainstorm.** Evidence: 30% improvement in causal identification from prospective-hindsight framing (Mitchell/Russo/Pennington 1989, via broomva.tech); BTF-2 found premortem/blind-spot analysis was the single biggest differentiator of the best forecasting agent (arXiv 2604.26106); explicit warning that "group discussion first produces conformity, not coverage" — private/independent generation must precede synthesis.

3. **HIGH — Treat the blinded Elo ranking's self-consistency as necessary but not sufficient; require an external/verification-heavy check before a claim is promoted, not just tournament wins.** Evidence: AI co-scientist's own critical review notes the Elo curve is self-scored and "can optimize for what the judge likes rather than what is true" (benjaminhan.net); Google's own design puts "the majority of the system's computation... into verifying hypotheses, not generating them" against external literature/databases (eesel.ai). Concretely: research-council's evidence-gate (excerpt + citation required) already does some of this — this finding says to weight *verification budget* over *generation/ranking budget* explicitly, and not let Elo alone gate promotion to FINDINGS.md.

4. **HIGH — De-bias the blinded pairwise Elo step with bidirectional/position-swapped queries and an abstain option, not just "blinded."** Evidence: position bias alone produces up to a 24-point aggregate skew across real evaluator datasets (OSCAR, arXiv 2609.24128) and can flip strict preferences even when responses are supposedly compared fairly (Fragile Preferences, arXiv 2506.14092). SCOPE's Bidirectional Preference Entropy (arXiv 2602.13110) is a cheap (2-call) concrete mechanism: query both orderings, compute an entropy-based disagreement score, and abstain/flag-as-tie rather than force a ranked winner when the two orderings disagree.

5. **MEDIUM-HIGH — Require model/persona diversity in the council roles, or explicitly document that debate benefit is unproven for a single-model council.** Evidence: deliberation only helped with diverse models + shared information (arXiv 2512.22625, 4% Log Loss reduction, p=0.017) and showed *no benefit* for homogeneous same-model debate; debate-outcome studies found "intrinsic reasoning strength and group diversity are the dominant drivers," not debate structure (arXiv 2511.07784). If research-council's roles all run on one model/prompt family, this is a load-bearing gap.

6. **MEDIUM-HIGH — Adopt AgentDebug-style root-cause tracing for the meta-review/failure-handling step: find the *earliest* critical error via counterfactual substitution, not just critique the final output.** Evidence: 24% higher all-correct accuracy, 26% relative task-success improvement from targeting the earliest causal step rather than surface symptoms (arXiv 2509.25370); "error propagation is the primary bottleneck" — an error introduced early (e.g., in Generation) but only caught at Ranking should be traced back and re-run from that point, not patched downstream.

7. **MEDIUM — Preregister the report's confirmatory claims/success criteria before the evidence-gathering phase that will test them, especially for claims the report will present as "verified."** Evidence: the p-hacking preregistration protocol (arXiv 2606.27687) and the AI-agent preregistration template (arXiv 2606.11217) both show this materially blocks HARKing; concretely, research-council could require the frozen goal + claim list to specify *what evidence pattern would count as verified vs. unverified* before the evidence search begins, and log any post-hoc changes to that criterion as an explicit deviation (as the practitioner case study does with a committed PREREGISTRATION.md).

8. **MEDIUM — Add a lightweight, deterministic "known-technique lookup" layer for domains with an existing structured method (TRIZ-style), instead of asking the LLM to recall/apply the method from memory.** Evidence: AutoTRIZ's deliberate design keeps the contradiction-matrix retrieval as a non-LLM deterministic function specifically "to ensure consistency and accuracy... mitigating the risk of generating incorrect information" (doi 10.1016/j.aei.2025.103312). Generalizes to: if the curiosity protocol or Generation role needs to apply a named method (5 Whys, base-rate tables, a rubric), retrieve/execute the mechanical parts deterministically and reserve the LLM for judgment calls.

9. **MEDIUM — Use median-of-samples (wisdom-of-crowds decoding) rather than majority-vote self-consistency for any numeric/quantitative sub-estimates inside the pipeline (e.g., confidence scores, effort estimates).** Evidence: WOC-median beat self-consistency-majority-vote with far fewer samples (5 vs 30) on guesstimation tasks (arXiv 2501.17310). Cheap to adopt wherever the pipeline currently asks multiple roles/passes for a numeric judgment and averages or votes.

10. **MEDIUM — Explicitly budget verification compute higher than generation compute, and instrument how much of the pipeline's token/time budget goes to each.** Evidence: Google's design choice (research.google / eesel.ai) and the SDBench/MAI-DxO cost-accuracy Pareto results (arXiv 2506.22405) both show orchestration that spends more on checking/testing than proposing wins on the quality-cost frontier — MAI-DxO beat off-the-shelf o3 on accuracy *while cutting cost 70%* through better test/evidence selection, not more generation.

11. **LOW-MEDIUM — If the curiosity protocol's "boundary" step is meant to find genuinely novel hypotheses, treat that as a hard, rarely-achieved bar, not a routine expectation.** Evidence: Heuresis found *zero* ideas rated "Original" across many scored search runs, and any novel ideas found never matched top known-recipe performance (arXiv 2606.25198). This suggests calibrating expectations/reporting language ("boundary-testing" claims should default to "unverified/speculative" unless independently corroborated) rather than treating boundary-spark output as reliably high-value.

12. **LOW — If the report ever surfaces model-generated confidence numbers (e.g., "70% confident this claim holds"), score/reward those with a proper scoring rule (Brier) rather than trusting verbalized confidence at face value, since plain RL/agent success signals measurably erode calibration.** Evidence: RLCR shows ECE drop from 0.46 to 0.21 OOD purely from adding a Brier-score reward term (arXiv 2507.16806); this is a training-time fix and may not directly transfer to a non-fine-tuned pipeline, but the qualitative warning ("ordinary optimization degrades calibration") applies to any scoring/ranking loop that only rewards binary success.

### R2-1. Differential diagnosis & diagnostic-error research: premature closure, anchoring, and LLM transplants

- **Foundational taxonomy** (Croskerry, via multiple secondary clinical-education sources, e.g. cordem.org acquired 2026-05-20, ubccpd.ca acquired 2026-05-01, rushem.org acquired 2026-08-08): the standard "Cognitive Dispositions to Respond" include **anchoring** ("perceptually lock on to salient features... too early... failing to adjust this initial impression in light of later information"), **premature closure** ("accepting a diagnosis before it has been fully verified... 'when a diagnosis is made, the thinking stops'"), **confirmation bias**, **search satisficing** (calling off the search once something plausible is found), and **availability bias**. Standard debiasing countermeasures named across sources: force a differential ("What else might this be?"), rule-out-worst-case-scenario, the "reverse listing" technique (write down findings that *don't* fit the leading hypothesis — if that list grows longer than the supporting list, reconsider), and "if my colleague proposed this diagnosis, would I agree?" as a perspective-shift check.
- **Quantified error contribution** (Misdiagnosis Tracker study, PMC12194747, published 2025-06-11, acquired 2026-09-04): "**Cognitive errors contributed to 65% of the misdiagnoses**, with anchoring and premature closure being most common," and "red flags were overlooked or dismissed in 58% of cases, typically due to inadequate re-evaluation of symptoms when new information became available."
- **The "acquiescence problem" — LLMs reinforce clinician anchoring rather than correcting it** (Dialogical AI for Cognitive Bias Mitigation / DiDi, mdpi.com 2076-3417/16/2/710, published 2026-01-09, acquired 2026-09-04): citing Goh et al., "physicians who utilized GPT-4 assistance achieved a mean accuracy of 76%, only marginally superior to the 74% obtained by those without assistance. Remarkably, however, **GPT-4 alone achieved 90% accuracy**... physicians tended to adhere to their initial diagnosis and often ignored GPT-4's suggestions when these contradicted their preexisting opinions... LLMs tend toward neutral, non-committal responses, which, instead of prompting practitioners to challenge their initial assumptions, often validate and reinforce prevailing cognitive patterns." Their fix (**DiDi**) splits the LLM into three forced roles — Framework Coach, Socratic Guide, and **Red Team Partner** (presents evidence-based alternatives) — specifically to create "necessary cognitive friction to overcome acquiescence." This is a *human-in-the-loop* pilot (case studies, not RCT), so treat as directional, not a measured population-level gain.
- **LLMs have their own, measured premature-closure rate** (Quantifying and Mitigating Premature Closure in Frontier LLMs, arXiv 2605.15000, acquired 2026-05-29): defines LLM premature closure as "inappropriate commitment under uncertainty." On MedQA/AfriMed-QA with the correct MCQ option removed, "models still selected an answer at high rates, with baseline **false-action rates of 55–81%** and 53–82%, respectively." On open-ended tasks: "inappropriate answers on an average of **30% of 861 HealthBench questions and 78% of 191 physician-authored adversarial queries**." Intervention tested: "Safety-oriented prompting... consistently reduced premature closure, including false action on unanswerable multiple-choice questions by **6–46 percentage points**, premature closure in standard open-ended settings by **4–8 points**, and premature closure under adversarial conditions by **9–20 points**. However... substantial residual failure remained, particularly in adversarial scenarios where premature closure rates often exceeded 50%." **This is a directly relevant, quantified, low-cost intervention** (a system-prompt instruction to abstain/clarify/escalate under uncertainty) with a measured but partial effect.
- **A distinct LLM-specific failure mode, not equivalent to human anchoring**: "Convergence Regression" (medrxiv 2026.03.27.26349583, published 2026-03-27, acquired 2026-06-10), N=50 NEJM cases / 150 runs on claude-sonnet-4: under unstructured sequential evidence delivery, "models correctly identify diagnoses at intermediate reasoning stages but **abandon them when subsequent evidence triggers pattern-matching to alternative diagnoses**... models access the correct diagnosis in 90% of cases but retain it in only 60%, creating a **30% Access-Stability Dissociation**." Their scaffold (Sequential Information Prioritization Scaffold, SIPS) "eliminates this gap entirely through forced hypothesis accountability: 80% access, 80% final accuracy, 0% Convergence Regression" — **but** "scaffolding reduces top-1 accuracy from 60% to 40%, a Convergence Hesitancy Paradox establishing that retention and convergence are architecturally distinct reasoning tasks requiring separate mechanisms." Explicit finding: this failure "is not anchoring... not premature closure... not confirmation bias" — it is a *new* pathology (correct hypothesis found, then discarded for a more "textbook-sounding" alternative). Direct relevance to research-council: a scaffold that forces hypothesis retention can fix retention while *independently* costing initial-convergence accuracy — the two need separate fixes, not one.
- **Narrative/register-based anchoring, orthogonal to demographic bias** (Same Facts, Different Diagnosis / NarrativeShield, arXiv 2607.27384, published 2026-07-31, acquired 2026-09-11): even with identical clinical facts and no demographic markers, "a shift in a model's diagnostic output that tracks sociolinguistic register rather than clinical content" was found "in every model tested, with a Narrative Anchoring Gap of 0.064 to 0.151." "Chain-of-thought reasoning and an explicit debiasing instruction reduce this only partially, and chain-of-thought's apparent gains are frequently confounded by a drop in accuracy." Their fix — **NarrativeShield**, a 3-agent pipeline that "structurally extracts and verifies clinical facts before diagnostic reasoning begins, decoupling what the model reasons over from how the patient's story was told" — "reduces the Narrative Anchoring Gap to near-zero (−0.004 to 0.037)... with a modest accuracy cost for most models." **Direct architectural pattern for research-council**: separate a fact-extraction/evidence-canonicalization pass from the reasoning-over-evidence pass, so surface framing of the input (who wrote it, how the goal was phrased) can't leak into judgment.
- **Multi-agent Delphi as an anchoring-resistant diagnostic protocol** (rigordesk.com, published 2026-07-24, acquired 2026-09-17): explicitly designed to prevent "diagnostic anchoring" cascades where "if Model A prematurely suggests a diagnosis, Model B and Model C will routinely adopt Model A's framing" — solved via "**Silent Extraction (Round 1)**: Models receive the patient record simultaneously. They cannot see peer responses. This prevents information cascades and early anchoring," followed by anonymous cross-review. (Vendor/product page, not a peer-reviewed study — logged as a design pattern, not a measured result.)

### R2-2. Full read of the 25,000-run "AI scientists" audit (arXiv 2604.18805): what interventions moved the needle?

Fetched the full paper text (not just the abstract) specifically to answer this. The paper ran a **trace intervention experiment**: injecting partial reasoning trajectories from prior successful or failed runs, at varying completeness (early steps 1–2 up through near-complete, steps *n*-2 or *n*-1), into a fresh agent's context. Findings:
- **Domain-dependent, and generally weak.** In workflow-construction domains (e.g., ML-based Property Prediction), injecting just one or two successful steps *did* exceed baseline performance. But in the more epistemically demanding domains — **Spectroscopic Structure Elucidation, Inorganic Qualitative Analysis, and Retrosynthetic Planning** — "partial interventions did not improve performance; gains emerged *only* when agents received near-complete successful trajectories (steps *n*-2 or *n*-1)."
- **Failed-trace interventions essentially did nothing**: "failed-trace interventions had little effect (success rates remained near baseline)."
- **No compounding benefit across repeated attempts**: "Under success-trace interventions at early steps, repeated-attempt success decay (Pass^k) remained similar to baseline" — i.e., giving an agent a head start didn't make it more *reliable* across repeated tries, only (sometimes) more likely to succeed once, and only in the easier domains.
- **Net conclusion, matching the abstract**: the only thing that reliably moved outcomes was handing the agent almost the entire correct answer already worked out — not a hint, not a partial trace, not a technique. This directly supports counter-evidence point #1 in the original findings: **scaffold-level interventions (including handing over reasoning trajectories, which is a stronger intervention than most prompting techniques) mostly failed to fix the underlying evidence-ignoring behavior**, and the authors' own conclusion is explicit: "outcome-based evaluation cannot detect these failures, and scaffold engineering alone cannot repair them... **until reasoning itself becomes a training target**, the scientific knowledge produced by such agents cannot be justified by the process that generated it." This is a strong caution against assuming *any* purely prompt/scaffold-level fix (including everything proposed in section (c) below) will fully close the evidence-ignoring gap — these are harm-reduction measures on top of a base-model-level limitation, not a cure.

### R2-3. A3 / fault-tree / 5-Whys: known failure modes of the methods themselves

- **5 Whys' definitive critique** (Alan J. Card, *BMJ Quality & Safety* 26(8), 2017, "The problem with '5 whys'" — cited consistently across lobehub.com acquired 2026-08-31, a dedicated Five Whys explainer acquired 2026-08-10, and two 2026 Medium critiques acquired 2026-06-05/07-07): the technique **"oversimplifies complex problems, follows a single causal chain when failures are multi-causal, and limits understanding of how processes actually fail."** Named structural flaws, consistently repeated across sources: (1) **gross oversimplification** — real incidents branch and interact, 5 Whys forces one linear path; (2) **single-root-cause assumption** — "insisting on one root cause is ideological, not empirical" for incidents that arise from *alignment of several factors*; (3) **distal-link fallacy** — no empirical basis for the claim that the most distant link in the chain is the most effective intervention point; (4) **inter-rater reliability failure** — "different analysts applying 5 Whys to the same incident reach different roots... this is a fundamental repeatability problem," with no comparative study located anywhere showing 5 Whys outperforms a plain causal discussion or a branching tool for any class of problem; (5) **the "Bad Apple" / blame trap** (John Allspaw, 2014, building on Dekker/Conklin/Leveson): the linear chain "tends toward 'who' and blame," terminating at "operator error" rather than the systemic conditions that made the error make sense at the time — Allspaw's proposed fix is to ask "how" (what conditions allowed this) rather than "why" (what single prior cause).
- **When 5 Whys is actually appropriate**, per the same sources: only for "simple, linear, deterministic failures" with one dominant physical/procedural cause (e.g., a machine stopped because a specific mechanical chain broke) — never as the sole technique for "patient safety, aviation, nuclear, or complex distributed systems" (lobehub.com). The self-described "honest boundary": use it as a five-minute triage prompt or teaching device for "don't stop at the first answer," not as the analysis itself.
- **The specific mechanism of failure that generalizes to agent pipelines**: "the technique provides **no constraints on which causal branch to follow, no requirement to test causal claims against evidence, no mechanism to identify when a chain is incomplete**" (Medium, "The 5 Whys Has a Design Flaw Nobody Talks About," 2026-03-21). This is structurally the same complaint as the "evidence is ignored in 68% of traces" finding above — an unconstrained "ask why" loop invites narrative closure rather than evidence-testing, in both humans and (per the audit) LLMs.
- **Fault Tree Analysis, its LLM-agent transplant, and its own failure modes**: JFTA-Bench (arXiv 2603.22978, acquired 2026-09-19) built a "JSON-based Fault Tree" textual representation specifically because raw natural-language fault trees are hard for LLMs to reason over faithfully. Measured LLM-agent failure mode on this task: "the primary failure mode of the assistant lies in **Planning errors**... the assistant may repeatedly ask about a node for which the user has already provided diagnostic feedback... in almost all instances where a path error occurs, the model **fails to recognize the mistake and make a correction**." I.e., even with a formal, branching (non-5-Whys) fault-tree structure, LLM agents still showed poor error-recovery once they went down a wrong branch — the branching structure alone didn't guarantee self-correction.
- **A3's Genchi Genbutsu ("go and see") as evidence discipline**: confirmed across A3-skill implementations (ahel.ai, marketplace.agentscli.com, both acquired 2026-08/2026-08-30) that the format enforces "Current Condition: state the facts only. No opinions, no causes yet," with an explicit refusal rule: "If the user has not provided actual data... stop and ask before guessing. An A3 with fabricated data is worse than no A3." This is the one RCA-adjacent method in this batch whose LLM-skill implementations *build in* an anti-hallucination gate as a hard stop rather than a best-effort instruction — a stronger and more concrete pattern than the 5 Whys or fault-tree literature offers.
- **Newer LLM-agent-specific root-causing work (beyond what Round 1 found)**: **AgentDebugX** (arXiv 2607.18754, acquired 2026-07-23) runs a "Detect → Attribute → Recover → Rerun" loop with a **cross-examination** step: two independent diagnostic passes (a global-trajectory read and a structure-guided bisection) each nominate a candidate root-cause step; if they disagree, the two candidates are adjudicated side-by-side rather than trusting either pass alone — "reducing root-cause selection from a search over the whole trace to a focused adjudication between two hypotheses." Measured: "28.8% exact agent-and-step accuracy... versus 21.7% for the strongest single-pass baseline" and repaired 13/73 failed GAIA tasks in one rerun vs. 4–6 for decoupled self-correction baselines, "improving overall accuracy from 55.8% to 63.6%." **This "two independent passes + adjudicate disagreements" pattern is structurally identical to the SCOPE bidirectional-judging fix from Round 1 (§ R1 judge-bias) and is a second, independent line of evidence for building disagreement-triggered adjudication into research-council's own root-causing/meta-review step**, not just its Elo ranking.
- **Counter-evidence that structural fixes alone don't solve agent RCA**: "Why Do AI Agents Systematically Fail at Cloud Root Cause Analysis?" (arXiv 2602.09937, published 2026-03-05, acquired 2026-09-22), 1,675 runs across 5 models on OpenRCA: "**Hallucination in Interpretation (71.2%)** and **Incomplete Exploration (63.9%) persist across all tested models at comparable rates regardless of capability tier**, establishing that these dominant failures originate from the shared agent framework rather than from individual model limitations... **prompt engineering alone cannot resolve the dominant pitfalls**, whereas enriching the inter-agent communication protocol reduces communication-related failures by **up to 15 percentage points**." Directly parallel finding to R2-2 above: prompt-level fixes underperform structural/architectural fixes for RCA-style tasks specifically.

### R2-4. Base-rate-first + Fermi decomposition in 2026 LLM forecasting agents

- **The "outside view first" ordering is the consistently-taught discipline, but with mixed direct evidence of causal effect**: several independent 2026 agent-skill implementations (superforecasting-skill on GitHub, acquired 2026-08-12; Akorchak:Forecast, acquired 2026-05-26/08-16; a generic "superforecaster" Claude subagent, acquired 2026-08-29) converge on the same enforced order: **Fermi-ize the question into 3–7 independent sub-questions → establish 2–3 reference classes and compute a weighted-average anchor probability *before* looking at case-specific evidence → only then apply inside-view adjustments.** One implementation states the rule explicitly as "the single most-violated rule": *"External-view base rate — state base from primary reference class **before** introducing personal facts."*
- **A concrete, enforced-order mechanism**: the superforecasting-skill repo describes "a deterministic Python engine [that] enforces a state machine that blocks the two most common forecast-killers: predictions without deadlines, and after-the-fact reinterpretation," with an explicit state machine `∅ → DRAFT → SCOPED → ACTIVE → UPDATED* → SETTLED → SCORED (auto Brier)` and illegal transitions rejected with errors. This is a non-LLM enforcement layer around the LLM's forecasting text — structurally the same pattern as AutoTRIZ's deterministic contradiction-matrix lookup from Round 1: **use code, not prompting, to guarantee ordering and prevent retroactive rewriting of the forecast.**
- **This reinforces, rather than newly resolves, the Round-1 tension**: Round 1 already found that prompting a model to "do Bayesian reasoning" or "be a superforecaster" (Schoenegger/Jones/Tetlock/Mellers 2025) often has *no measurable effect or backfires*, while the *enforced, code-gated ordering* (state machine blocking premature commitment, deterministic anchor computation before evidence) is a structurally different and stronger intervention than a persona/framing prompt. No 2025-2026 paper found in this round provides a controlled, ablated measurement isolating "enforced base-rate-first ordering" as its own variable (as distinct from the whole Fermi+premortem+bias-check pipeline) — this remains an open question rather than a confirmed finding.
- **BTF-2 (already in Round 1, arXiv 2604.26106) remains the best available *ablated* evidence** that specific components of the superforecasting pipeline matter differentially: it isolates premortem/blind-spot analysis as the dominant driver of the accuracy gap between the best and average frontier forecasting agent, ahead of generic "more compute" or "more reasoning" — i.e., of the whole superforecasting toolkit, the premortem component specifically is the one with the clearest measured causal signal, more so than base-rate anchoring per se.

### Round 2 — additional upgrade ideas for research-council

13. **HIGH — Separate "evidence extraction/canonicalization" from "reasoning over evidence" as two distinct passes, gated so the second pass cannot see how the first pass's input was framed.** Evidence: NarrativeShield (arXiv 2607.27384) reduced a framing-driven bias from 0.064–0.151 down to near-zero (−0.004 to 0.037) by exactly this separation, with only a modest accuracy cost. Directly applicable to research-council's evidence-gate: extract the excerpt/claim first, in a pass that doesn't see the requester's framing or preferred conclusion, before the role that judges it.

14. **MEDIUM-HIGH — Add an explicit "reverse listing" / disconfirming-evidence-length check as a hard gate before any hypothesis is allowed to close.** Evidence: standard clinical debiasing practice (Croskerry-derived sources) and directly quantified: cognitive errors (mostly anchoring + premature closure) drove 65% of misdiagnoses in a 2025 study (PMC12194747). Concretely: before Reflection/Ranking accepts a hypothesis, require a listed count of disconfirming vs. confirming evidence items, and block closure if the disconfirming list wasn't actively generated (not just "none found").

15. **MEDIUM-HIGH — Treat a disagreement between two independent root-cause/diagnosis passes as a trigger for adjudication, not a tiebreak by majority or default.** Evidence: AgentDebugX's cross-examination step (arXiv 2607.18754) beat single-pass root-causing by 7 points of exact accuracy (28.8% vs 21.7%) and roughly doubled single-rerun repair rate (13/73 vs 4-6/73) specifically via a "two independent hypotheses, then adjudicate" structure — the same shape as the SCOPE bidirectional-judging fix from Round 1, now confirmed in a second, unrelated domain (agent debugging vs. pairwise judging).

16. **MEDIUM — Do not let research-council's meta-review/root-cause step default to a single linear "5 Whys"-style chain; require it to check for multi-cause convergence before accepting one root cause.** Evidence: the 5 Whys literature (Card 2017, Allspaw 2014, and multiple 2026 practitioner critiques) is unusually consistent that single-chain RCA has an *inter-rater reliability failure* (different analysts/re-runs reach different "root causes" from the same evidence) and a *distal-link fallacy* (no evidence the most distant cause is the most fixable one). If research-council's failure-handling ever asks "why did this claim/evidence chain fail," it should default to a branching/multi-cause check (as A3's Fishbone step or a cause-map does) rather than a single "why" chain, especially since the OpenRCA study (arXiv 2602.09937) found the dominant LLM-agent failure modes (hallucinated interpretation 71.2%, incomplete exploration 63.9%) are exactly the failure modes a single unconstrained "why" chain cannot catch.

17. **LOW-MEDIUM — Where research-council enforces a strict order of operations (e.g., "gather evidence before forming a claim," "freeze the goal before research"), consider encoding that order as a deterministic gate/state-machine rather than an instruction, mirroring the base-rate-before-evidence and forecast-before-deadline gates in the superforecasting-skill implementations.** Evidence is only indirect/design-pattern level here (no controlled ablation found isolating this specific mechanism), so this is rated lower confidence than items 1-4 and 13-15, but it is a recurring, cheap, low-risk pattern across three independent codebases (AutoTRIZ's deterministic matrix lookup, the state-machine forecasting skill, A3's hard data-fabrication gate).

### Round 2 — additional counter-evidence

10. **Handing an agent a near-complete correct reasoning trace was the *only* thing in the audited intervention set that reliably helped**, and even that failed in the harder epistemic domains until the trace was almost fully complete (arXiv 2604.18805 full text). This means most of the upgrade ideas in this document (structured matrices, premortems, deterministic gates) are optimizing around the edges of a problem the paper's authors argue is a base-model training-target issue, not a scaffold issue — they should be read as harm-reduction, not a claim that research-council's procedure will make its underlying model reason like a scientist.
11. **LLMs can *actively undermine* human debiasing rather than support it** — the Goh et al. finding (via mdpi.com 2076-3417/16/2/710) that physician+GPT-4 accuracy (76%) barely beat physician-alone (74%) while GPT-4-alone hit 90%, because physicians anchored on their own prior diagnosis and discounted the LLM's (correct) alternative. This cautions against assuming a "second opinion" or "red team" role in a human-facing part of research-council's workflow will actually be *heeded* rather than politely ignored.
12. **A structural fix for one failure mode can reduce a different desirable property** — SIPS eliminated Convergence Regression entirely (0%) but dropped top-1 accuracy from 60% to 40% in the same study (medrxiv 2026.03.27.26349583). Any scaffold added to research-council to fix one named failure mode should be checked for this kind of trade-off against an unrelated metric, not just validated against the failure mode it targets.

- Does research-council's meta-review ever perform single-chain "why" root-causing on a failed run, and if so, does it check for multi-cause convergence (upgrade #16)?
- No controlled study was found in either round that isolates "enforced base-rate-before-evidence ordering" as a standalone causal variable in agent forecasting accuracy — this would need a bespoke ablation (comparable to BTF-2's premortem-isolation design) to answer definitively; flagging as an evidence gap rather than assuming the ordering convention is validated.
