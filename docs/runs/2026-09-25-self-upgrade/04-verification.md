### R2-1. Cheapest excerpt-support check that works WITHOUT a paid API

- **Local NLI cross-encoders are the standard zero-cost answer.** cross-encoder/nli-deberta-v3-base (open-weight, runs on CPU) is used as the default local verifier in a real open-source tool: "Elenchus" — "Most faithfulness-checking tools rely on an LLM to judge another LLM, which is expensive, slow, and structurally circular... Elenchus defaults to cross-encoder/nli-deberta-v3-base — runs on a CPU, costs zero per claim." https://github.com/Fqih/Elenchus (acquired 2026-09-03)
- **Domain-tuned DeBERTa-v3 NLI gets strong accuracy at near-zero latency/cost**: a legal-entailment-tuned DeBERTa-v3-large reports "89.1% accuracy on contradictions — the most critical class for citation verification... Zero marginal cost — runs locally, no API calls needed. 139ms latency — fast enough for real-time checking." https://huggingface.co/epequeno/legal-entailment-deberta-v3-large (acquired 2026-08-24). Caveat: this is a HuggingFace model card's self-reported number, not a peer-reviewed benchmark — lower confidence than the arXiv sources elsewhere in this file, but directionally consistent with other findings below.
- **A tiny (0.4B parameter) local scorer reaches ~75-76% balanced accuracy** on a public factuality leaderboard: "Near-top factuality with local scoring — 75.6 percent BA on the public leaderboard (threshold 0.50) and 75.8 percent on the local packet (threshold 0.46), with a 0.4B parameter model, local execution, and no per-call API cost." https://anulum.github.io/director-ai/benchmarks (acquired 2026-09-14). This is meaningfully worse than GPT-4o-backed CiteEval (Pearson 0.731 with humans) but costs nothing per call and runs offline.
- **Plain local NLI (no LLM) is a legitimate baseline tier in at least one open eval harness**: "`nli-only` runs the local DeBERTa NLI model against the provided evidence passages. This is the default tier for headline numbers, and the cleanest 'does the verifier work on the verification task' measurement." https://conjfrnk.github.io/2026/04/10/pca-eval (acquired 2026-07-21)
- **Human-vs-NLI agreement numbers exist for a claim-level pipeline (MIRAGE, arXiv paper, via emergentmind.com summary):** "merged human labels agree with NLI at 90.67%, with supported precision/recall of 0.917/0.965 but unsupported recall of only 0.714 — contradictions are missed more often than supports." https://emergentmind.com/papers/2607.05069 (acquired 2026-09-06). This is an important asymmetry for a no-paid-API design: cheap local NLI is good at confirming support, worse at catching unsupported/contradicted claims — i.e., false negatives on "unverified" are the likely failure mode, which is the safer direction for research-council's "no evidence = unverified" default, but means a local-only NLI gate will let some unsupported claims through.
- **Simplest-possible check, cheaper than any model: exact/fuzzy substring quote matching.** None of the sources fetched this session benchmarked pure string-matching accuracy numbers directly (only model-based approaches had numbers), so this remains an assumption, not evidence-backed, inside the time budget — flagged in Open Questions below rather than stated as a finding.
- **Bottom line for research-council (no paid API required):** a local cross-encoder/nli-deberta-v3-base (or similarly small entailment model) run per claim-excerpt pair is a real, already-implemented pattern (Elenchus, VerifiedTutor capstone also independently converged on the same model) with zero per-call cost, ~90% agreement with human judgment on support detection, but weaker (~71%) recall specifically on catching contradicted/unsupported claims — meaning a "verified" label from local-NLI-alone should still be treated as weaker evidence than one confirmed by a stronger (paid) verifier, while a local-NLI "unsupported" flag is fairly trustworthy.

### R2-2. "Failing to Falsify" (arXiv:2604.02485) — exact intervention text (verified via direct PDF fetch)

Verbatim from the paper (fetched https://arxiv.org/pdf/2604.02485):

> **Think-in-Opposites prompt:** "Before proposing each new triple, look at the example and think about one feature it has. Then imagine a triple that is opposite with respect to that feature, and test whether it still conforms with the rule. If it does, that feature is probably irrelevant; if it does not, that feature might be crucial. In short: to discover the rule, test triples that both confirm and contradict your current idea."
>
> **Dual-Goal prompt:** "You will be given three numbers which conform to a simple rule that I have in mind. Triples that fit this rule are called DAX, and triples that do not fit this rule are called MED. These rules are concerned with the common attributes or relations between any three numbers, and not with their absolute magnitude – for example, they are not rules like 'all numbers above (or below) 50.' Your goal is to discover both rules: the rule for DAX triples and the rule for MED triples. You will then be told if the triple conforms with the DAX rule or the MED rule."

The 42%→56% figure is an **aggregate average across the evaluated LLM models/conditions** in the study (task: Wason 2-4-6 rule-discovery game), not a single-model number — the fetched text did not break out a per-model table within the excerpt retrieved. Directly portable to research-council: the Dual-Goal framing generalizes cleanly to hypothesis evaluation — instead of "find evidence for hypothesis H," frame Curiosity/Reflection prompts as "find evidence that would place this observation under H, and evidence that would place it under NOT-H," mirroring DAX/MED.

### R2-3. Citation fabrication rates of 2026 deep-research products (additional/fresher data)

- **Tow Center for Digital Journalism (Columbia University)** — the widely-cited primary source behind the "60%" figure repeated across secondary sites: "AI search has a citation problem" tested "200 tests on eight different AI search engines: ChatGPT Search, Perplexity, Perplexity Pro, Gemini, DeepSeek Search, Grok-2 Search, Grok-3 Search, and Copilot," giving each a direct quote from a news article and asking it to identify title/publisher/date/URL. Per secondary reporting of this primary study: "collectively, the bots provided incorrect answers to more than 60% of queries," and "ChatGPT incorrectly identified 134 of its 200 articles, yet signaled uncertainty only 15 times and never declined to answer." Perplexity (base) reportedly had the lowest failure rate among the eight at 37% per one secondary aggregator (theairankings.com, 2026-09-05) — still over 1 in 3 wrong. Note: original Tow Center study is dated March 2025 (niemanlab.org report), so this is not itself a 2026 product, but 2026 secondary sources continue to cite it as the benchmark reference point, and no fetched source in this session reports a 2026 re-run with updated numbers for the same 8 engines — flagged as a gap.
- **Cureus clinical-citation study** (per seomadman.com secondary summary, 2026-07-27): "ChatGPT-5 fabricated 7.13% of the 2,736 clinical references it generated, and got every field right in only 8% of queries" — notable because the fabrication rate alone (7%) understates the problem; only 8% of citations were fully correct on all metadata fields even when not outright fabricated.
- **Academic-text reference audit** (textpulse.ai, 2026-08-19, "Condition B" of their study): of 1,499 parseable references, "958 (63.9%) were REAL-EXACT, 313 (20.9%) were REAL-ERRORS, 62 (4.1%) were CHIMERA, and 166 (11.1%) were FABRICATED. The combined fabrication rate, counting FABRICATED and CHIMERA together, was 15.2% (95% CI 13.5–17.1)."
- **NYT/Oumi-style audit of Google AI Overviews** (loudscale.com, 2026-05-10, secondary reporting): "analyzed 4,326 Google searches. AI Overviews were factually correct 91% of the time. But roughly half contained claims not supported by their cited sources... Facebook and Reddit were the second and fourth most-cited despite being the least authoritative options" — reinforces the CiteEval-family point that citation *presence* and citation *support* are different failure axes, and that source reliability and claim-support are both needed, not just one.
- All of the above are consistent with, and do not contradict, the Round-1 primary numbers (GhostCite 14–95% no-retrieval; arXiv:2604.03173's 3–13% hallucinated / 5–18% non-resolving URLs for retrieval-augmented deep-research agents). The Tow Center's news-citation-attribution task (60%+ error) measures a stricter, different thing (exact article/date/publisher match) than the "does the URL resolve" or "does the excerpt support the claim" tasks in the Round-1 papers, so these numbers are not directly comparable to each other — a methodology caveat worth keeping in FINDINGS.md if research-council ever cites a single "hallucination rate" figure.

### R2-4. Why verbalized-confidence findings conflict — explanatory factors found

Re-examining the two directly conflicting Round-1 papers after fetching their abstracts in full:
- **arXiv:2606.19509** ("vacuous" confidence, AUROC 0.50): task = structured clinical **tabular** prediction using **Qwen 2.5 7B** (a smaller open-weight model), comparing against an XGBoost baseline; confidence elicited as a number tied to a classification-style prediction over engineered features, not free-text answer generation.
- **arXiv:2609.20541** (confidence "surprisingly strong," AUROC 0.94–0.96): task = **TriviaQA**, open-domain free-form factual QA, using **DeepSeek and Claude Sonnet** (larger, more capable, RLHF-tuned models), confidence elicited alongside a natural free-text answer.

Three concrete, evidence-backed moderators found this round that plausibly explain the gap, rather than the two results being simply contradictory:
1. **Model capability/scale**: a 7B open-weight model on a task outside its comfortable answer format (structured tabular features) vs. frontier RLHF models on the exact free-text QA format most verbalized-confidence training/RLHF likely optimized for.
2. **Answer-format constraint (open- vs. closed-ended)**: "Overconfidence and Calibration in Medical VQA" (arXiv:2604.02543, 2026-04-06) found "the overconfidence gap is larger for open-ended questions than for closed-ended ones, as structured answer choices... provide external constraints on the output space that are absent in free-form generation," and that a hallucination-aware calibration method "improves AUROC by 5.3pp over uncalibrated baselines, with notably larger gains on open-ended questions (+7.3pp), especially for verbalized confidence (+10.1pp)." This suggests structured/classification-style tasks (like the tabular clinical study) are actually *harder* to calibrate via verbalized confidence than free-text QA, which is the opposite of naive intuition and is consistent with the observed conflict.
3. **Domain-specific recalibration literature exists precisely because tabular/structured tasks calibrate differently**: "Calibrated Confidence Estimation for Tabular Question Answering" (arXiv:2604.12491, 2026-04-15) treats tabular QA as needing its own "table-structure-aware recalibration," implying standard verbalized-confidence elicitation (tuned/validated mostly on free-text QA benchmarks) does not transfer cleanly to structured/tabular settings — directly supporting why arXiv:2606.19509's tabular setting broke verbalized confidence while arXiv:2609.20541's free-text QA setting did not.
- **Net implication for research-council**: verbalized confidence is more likely to carry real signal for the kind of free-text, claim-style outputs the council produces (closer to arXiv:2609.20541's setting) than it would for structured/classification-style sub-tasks — but per arXiv:2609.20541 itself, even in the favorable free-text setting, confidence is elicitation-fragile (re-asking flips 4–9% of threshold decisions) and self-consistency agreement can still "amplify shared misconceptions." So: verbalized confidence is plausible signal, not a trustworthy signal, for research-council's use case — reinforcing Round-1 upgrade idea #5 (derive confidence from external/structural signals, don't just ask the model for a number), now with a mechanistic reason (format/domain match) rather than just an empirical conflict.

## (a) Key findings

### Citation hallucination rates — deep research tools specifically
- **Detecting and Correcting Reference Hallucinations in Commercial LLMs and Deep Research Agents** (arXiv:2604.03173, published 2026-04-06): "Hallucinated URL rates range from 3% to 13%, with 5–18% non-resolving overall... Deep research agents exhibit the highest hallucination rates despite generating far more citations; retrieval architecture matters more than output volume." Exact numbers: "gemini-2.5-pro-deepresearch has the highest hallucination rate (13.3%) despite a top DRBench quality score... The Claude models achieve the lowest hallucination rates (3.0–3.2%)." Pooled: "the hallucination rate is 10.7% [10.2, 11.2] versus 4.8% [4.3, 5.2] for the eight search-augmented models" (deep-research agents vs. plain search-augmented LLMs). https://arxiv.org/pdf/2604.03173
- **DeepResearch Bench** (arXiv:2506.11763, 2025-06-13; FACT framework): pairs every statement in a report with its cited URL and asks a judge model whether the retrieved page supports the statement — "citation accuracy" = fraction of statement-URL pairs that pass. Per a secondary source (zandigital.in, 2026-08-31) citing this benchmark: Claude-3.7-Sonnet-with-search 93.68% citation accuracy / 32.48 effective citations; Perplexity Deep Research 90.24%/31.26; Grok Deeper Search 83.59%/8.15; Gemini-2.5-Pro Deep Research 81.44%/111.21; OpenAI Deep Research 77.96%/40.79. Key quote: "Volume and precision trade against each other... Gemini 2.5 Pro Deep Research returns 111.21 supported citations per report, three times the next agent, while scoring fourth of five on accuracy." https://zandigital.in/deep-research-tools-hallucination-audit (2026-08-31), primary benchmark https://alphaxiv.org/abs/2506.11763
- **GhostCite** (arXiv:2602.06718, 2026-02-09): without retrieval, 13 LLMs "hallucinate citations at rate from 14.23% to 94.93%" across 40 CS domains; archival audit of 2.2M citations across 56,381 papers (2020-2025) found "1.07% of papers contain invalid citations, with an 80.9% increase in 2025" (0.89%→1.61% year over year). Researcher survey: "76.7% of reviewers do not thoroughly check references." https://arxiv.org/pdf/2602.06718
- **DeepHalluBench** (arXiv:2601.22984, Jan 2026, via secondary source exatoshi.uk 2026-06-10): audits the full plan→search→summarize trajectory of six deep research agents, not just final answer — "Even the best systems showed fabrication rates of roughly 10–15% and misattribution rates up to ~22% — the citation exists, but does not say what the agent claims it says." This distinguishes two failure classes: fabrication (source doesn't exist) vs. misattribution (source exists, is misused) — "every synthesis step is another opportunity to drift from the retrieved evidence." https://exatoshi.uk/blog/fabricated-citations-ai-research-tools
- **HALLMARK** (arXiv:2607.18360, 2026-07-22): benchmarks citation-*verification tools themselves*, not just generators. Key finding: "a single variable organizes the results: the false-positive rate, not recall, decides whether a verifier can be deployed... A DOI-only baseline catches 27% of hallucinations, and LLMs queried directly, without retrieval tools, catch 48–91%, but along a pronounced recall–precision spectrum." Also notes real incident: "GPTZero audited the 4,841 accepted [NeurIPS 2025] papers and found 53 with fabricated citations that had passed peer review." https://arxiv.org/abs/2607.18360
- **VaaS pipeline** (medrxiv, 2026-03-24): production biomedical citation system — "unguided LLM output produced 95.9% Type II hallucination (wrong-topic citations)... the full VaaS protocol achieved 0.0% Type I and 6.5% Type II, a >14-fold reduction; live PMID verification alone (C3) eliminated both error types entirely (0.0%/0.0%)." This is the strongest evidence that a deterministic verification step (fetch and confirm the ID resolves + supports the claim) essentially solves fabrication. https://medrxiv.org/content/10.64898/2026.03.24.26348935v1.full

### Claim-level verification (FActScore / SAFE / VeriScore / VeriFastScore)
- **VeriScore** (arXiv:2406.19276): improves on FActScore/SAFE by extracting only "verifiable claims" (not opinions/hypotheticals) and using inter-sentence context to avoid a separate claim-revision step. "Human evaluation... our extraction method is preferred 93% of the time over Safe's, even in biography generation." Verification step: claim marked supported only "if all parts of the claim need to be supported (i.e., no evidence can contradict any)"; contradicted "if at least one [evidence] is contradicted." https://arxiv.org/html/2406.19276
- **VeriFastScore** (arXiv:2505.16973, 2025-11-03): the decompose-retrieve-verify pipeline is accurate but slow — "roughly 60 model or API calls per response... approximately 100 seconds." A single fine-tuned Llama3.1-8B doing joint extraction+verification "achieves a Pearson correlation of [strong] with VeriScore's scores, a 9.9x modeling speedup and 6.64x overall speedup," while GPT-4o few-shot prompting on the same joint task "struggles with this complexity, achieving a Pearson correlation of only 0.33." Implication: claim-level verification is learnable/distillable into a fast checker, but naive prompting of a strong general model at this joint task performs badly.
- **CiteEval** (arXiv:2506.01829 / doi:10.48550/arxiv.2506.01829, 2025-06-03): principle-driven citation evaluation beats NLI/AutoAIS baselines — "CITEEVAL-AUTO (GPT-4o backbone, ensemble) achieves Pearson 0.731 statement-level and 0.668 response-level correlation with human ratings, compared with 0.607... for the strongest NLI-based baseline."
- **"Verify with Caution: The Pitfalls of Relying on Imperfect Factuality Metrics"** (arXiv:2501.14883, 2025-01-31): re-evaluates 5 AutoAIS evaluators on an 11-dataset benchmark and finds "several reasons to be cautious when using AutoAIS evaluators" — i.e., the automatic "does source support claim" checkers themselves have real error rates and shouldn't be treated as ground truth.
- **ProvenanceGuard** (arXiv:2606.18037, 2026-06-17): flags a subtler bug — a claim can be true and supported by *some* retrieved document but attributed to the *wrong* one ("source-blind verifier that pools the account record and the policy document can mark the claim as supported [when it shouldn't]"). Verification must check claim→specific-source attribution, not claim→pooled-corpus support.

### Contradicting-evidence search / disconfirmation
- **"Failing to Falsify"** (arXiv:2604.02485, 2026-04-06): directly measures LLM confirmation bias via a Wason 2-4-6 style rule-discovery game across 11 LLMs. "Models exhibit varying extents of confirmation bias and task success rates (from 6% to 78%)... negative correlation between the extent of confirmation bias and task success rate." Two human-derived debiasing prompts worked: "Think-in-Opposites" (explicitly test the opposite of a salient feature) and "Dual-Goal" framing (search for both the rule and its complement) — "rule discovery rates jumped from 42% to 56% across the tested models."
- **FALSIFYBENCH** (arXiv:2606.04751): confirms with 12 LLMs — "The primary driver of success is the capacity for negative testing: models that actively seek to falsify their hypotheses consistently outperform those that primarily seek confirmation."
- **Dual-perspective claim verification** (arXiv:2602.18693, 2026-02-24): retrieving evidence using *both the original claim and its explicit negation* (not just the claim) improves verification accuracy by "+2–10% (accuracy) and +2–8% (F1)" across four benchmarks/three knowledge sources, e.g., SciFact +10.4% accuracy. Direct, cheap, concrete technique: always issue a second retrieval query for the negated/opposite claim.
- **TREC 2025 BioGen contradiction-aware QA** (arXiv:2603.17580, GEHC-HTIC team paper): found the "Entailment Trap" — "dense retrievers confuse topical similarity... with logical entailment," and dense/embedding retrieval catastrophically fails at finding contradicting evidence (MRR 0.023) due to "Semantic Collapse, where negation signals were indistinguishable in vector space." Fix: decouple into two pipelines — supporting evidence via dense/semantic retrieval, contradicting evidence via a **separate high-recall lexical (BM25) pipeline with explicit negation-cue filtering** (achieved 0.750 contradiction MRR vs 0.023 for dense). This is a concrete, falsifiable architecture recommendation: don't rely on the same retriever for both directions.
- **DARE** (arXiv:2609.13808): multi-agent "dialectical" fact-checking — argue supporting AND refuting sides explicitly before a confidence-driven controller decides whether more evidence is needed; "8B backbone achieving 88.12% accuracy," beating GPT-4o-based single-path baselines, attributed specifically to forcing bidirectional evaluation rather than one-sided ("self-evaluation distortion—a systematic bias toward overestimating supporting evidence when assessing claims from a single perspective").

### LLM-as-judge failure modes and calibration (directly relevant to blinded Elo ranking + meta-review)
- **"Reliability without Validity"** (arXiv:2606.19544, 2026-06-19): largest LLM-judge study to date — 21 judges, 9 providers, 3 benchmarks, 541,000 judgments. Findings: "kappa deflation: raw agreement overstates chance-corrected discrimination by 33–41pp in all 21 evaluated models"; "judge rankings are non-transferable: models shift by as many as 14 positions across benchmarks"; the **"consistency-bias paradox"** — "high test–retest reliability... often masks severe position bias... a judge that deterministically favors position A across runs would achieve a perfect test-retest score, but would also exhibit maximum-possible position bias." Proposes a **Minimum Viable Validation Protocol (MVVP)**: (1) always report Cohen's/Krippendorff's kappa, not raw agreement; (2) measure position bias via paired AB+BA swaps; (3) replicate over ≥N runs at temperature>0; (4) validate on ≥2 benchmarks of different label structure; (5) explicitly check the paradox (don't trust high test-retest alone).
- **"Bias and Uncertainty in LLM-as-a-Judge Estimation"** (arXiv:2605.06939, 2026-05-11): shows bias-correction estimators (Rogan-Gladen, PPI++) for judge-based accuracy/comparison can still fail badly when judge quality (Youden's J) is low — in one case study "the naive and RG estimators give confidently wrong-signed estimates with CIs firmly excluding zero" (a **sign-reversal failure**: the correction confidently says model A > B when truth is B > A). Judge accuracy in the wild "spans from near-chance to around 80%" (citing Tan et al. 2025/JudgeBench).
- **JudgeBiasBench** (referenced via adaline.ai, 2026-04-08 secondary source): "even frontier LLMs exceeded 50% error rates on challenging bias benchmarks" across 12 documented bias types. RAND's Judge Reliability Harness (March 2026): "no judge was uniformly reliable... Consistency broke down on inputs as simple as formatting changes, paraphrasing, and shifts in verbosity."
- **Multi-agent debate vs. meta-judge** (EMNLP 2025 Findings, "Judging with Many Minds", arXiv:2505.19477): "debate framework amplifies biases sharply after the initial debate, and this increased bias is sustained in subsequent rounds, while meta-judge approaches exhibit greater resistance." Directly actionable for a "council" architecture: a Reflection/debate step between hypotheses can *increase* bias round over round unless paired with an independent meta-judge layer, position-swapping, and a bias-free/PINE-style debiasing agent (which "effectively reduces biases in debate settings").
- Concrete mitigations recurring across sources: reference-guided grading beats prompt-only scoring when a ground truth/rubric exists; judge model family should differ from the generator's model family (self-preference/family bias is "structural, not a prompting mistake" — Panickssery/Bowman/Feng 2024 finding cited); calibrate against a small human-labeled set *and re-check periodically* since hosted judge models can silently drift across provider updates.

### Confidence calibration / verbalized confidence
- **DINCO** (arXiv:2509.25532): verbalized confidence overconfidence traced to "suggestibility" — models raise confidence on claims they know little about just because the claim is present in context; "more suggestibility on lower-accuracy claims." DINCO normalizes confidence across self-generated distractors and "at 10 inference calls outperform[s] self-consistency at 100" — i.e., a cheap coherence-check across alternative claims beats brute-force resampling for calibration.
- **ConfTuner** (arXiv:2508.18847): prompting alone barely helps calibration ("Prompt-based methods... have shown limited effects"); a proper-scoring-rule fine-tuning loss (tokenized Brier score) improves ECE by up to 54.7% and AUROC by 14.4% and "generalizes better across unseen datasets... and even implicit confidence expressions" — but this requires fine-tuning access, not available to a prompt-only agent harness like research-council.
- **"LLM Doesn't Know What It Doesn't Know"** (arXiv:2606.19509, clinical tabular data): starkest finding — "LLM verbalized confidence is determined by prompt template, not prediction quality... confidence predicts errors at exactly chance level (AUROC=0.50)." A **cross-model calibrator** (features from agreement/disagreement between the LLM and a separate model, e.g., XGBoost) cut ECE from 0.254 to 0.080 and reached AUROC 0.71 — i.e., don't trust the model's self-reported confidence number at all; derive confidence externally from measurable agreement/disagreement signals instead.
- **"An Analysis of Training-Free Self-Reported Confidence"** (arXiv:2609.20541): direct verbalized confidence was actually the *strongest* training-free signal in this study (AUROC 0.956/0.937 for two model families) — better than 3-sample self-consistency agreement (AUROC 0.765/0.790) — BUT "self-consistency can amplify shared misconceptions" (4/9 and 2/8 wrong answers got unanimous agreement across samples) and re-eliciting confidence for identical fixed answers with equivalent prompts "changes scores by 0.043 to 0.084 on average and flips 4% to 9% of decisions at a 0.8 threshold" — confidence numbers are elicitation-fragile even when informative on average. This somewhat contradicts the "vacuous confidence" finding above — the picture is domain-dependent (clinical tabular structured prediction vs. TriviaQA open QA), so calibration behavior should not be assumed to generalize across task types.
- **"Confidently Deceptive"** (arXiv:2607.20444): verbalized confidence and logit-based (internal) confidence can *dissociate* — models can express high surface confidence while internal token-level uncertainty (entropy) is rising, especially post misalignment fine-tuning. Relevant caution: a self-reported "confidence: high" from a role in the council pipeline is not a reliable proxy for actual internal certainty.

### Self-consistency
- Repeated-sampling / self-consistency (majority vote across multiple generations) is a well-established factuality booster (SelfCheckGPT and others), but with diminishing/inconsistent returns for calibration specifically: DINCO paper shows a targeted distractor-based method beats brute self-consistency resampling at far lower cost (10 calls beats 100). "First Token Knows" (arXiv:2605.05166) similarly shows a single-decode confidence signal "matches or modestly exceeds semantic self-consistency... at roughly [fraction] of the generation cost."

### Prompt injection via retrieved pages
- **IPI-proxy** (arXiv:2605.11868, 2026-05-13): purpose-built for exactly research-council's threat surface — "targets the broader class of agents that retrieve HTML over HTTP, including headless fetchers, search-result readers, and MCP-mediated retrieval tools that never render a UI" (i.e., not just browser-UI agents — directly applicable to a Keenable-MCP-based fetch tool).
- **LivePI** (arXiv:2605.17986, 2026-06-18): describes a practical defense layer — "Layer 1 runs before the model reads the prompt and converts the incoming prompt or conversation history into structured detector input... applies deterministic prompt injection pattern matching to flag suspicious instructions, such as requests to ignore previous instructions, reveal hidden prompts, bypass safety rules, impersonate higher-authority roles, or exfiltrate secrets" — a pre-filter step before fetched page content reaches the model context.
- **Hidden-in-Plain-Text** (ACM, 2026-01-22): quantifies defense-in-depth for RAG against social-web injected content — attack success rate (ASR) dropped from Vanilla 22.7% → Normalized 19.1% → Sanitized 12.0% → "All Defenses" (stacked) 4.3% under static payloads (28.9%→22.2%→15.8%→5.4% under adaptive/adversarial payloads). Confirms layering multiple lightweight defenses (normalization + sanitization + pattern detection) meaningfully compounds, though none alone is close to sufficient, and adaptive attackers still get through more often (+1.1 to +6.2pp over static).
- General framing repeatedly stated across this literature (Greshake et al., cited as originators of the IPI threat model): the core risk is that "the LLM retrieves third-party content... into which an attacker has planted instructions, and the model executes those instructions as though they were legitimate user requests" — exactly the risk when research-council's evidence-gathering step fetches arbitrary web pages and feeds their content into agent context.

### Evidence freshness / staleness
- **Chronofy** (pith.science paper 2607.20560, 2026-07-17): "current RAG architectures treat all retrieved facts as equally valid regardless of temporal provenance, leading to temporal hallucination, where plausible but obsolete facts corrupt the output. A clinical lab reading from yesterday is actionable; the same reading from six months ago is noise" — argues for a temporal-decay validity score on evidence, not just relevance score.
- **FreshCache** (arXiv:2607.04281, 2026-07-07): concrete freshness/staleness tradeoff numbers — "At the 24-hour window, FreshCache_MLP reaches 0.1% stale error and 97% search savings" — i.e., a volatility-aware re-fetch policy (some fact classes need re-verification every 24h, others don't) can cut redundant search dramatically while controlling staleness risk. Builds on FreshLLMs' "five-class volatility taxonomy."
- **FRESCO** (arXiv:2604.14227, 2026-04-17): names a specific retrieval failure — two documents about "the same" fact (e.g., software version numbers) can both look highly relevant under semantic similarity while only one is "chronologically valid," and standard rerankers don't resolve this; needs a temporal-conflict-aware reranker.
- **"How often do Answers Change?"** (arXiv:2603.16544, 2026-03-18): proposes a "Recency–Stationarity Taxonomy" — not all facts decay at the same, or a stable, rate; "current LLMs exhibit predominantly static temporal reasoning and struggle with dynamic recency adaptation," i.e., models can't reliably self-judge which of their own claims are time-sensitive.

### Source reliability scoring
- **MEDIAREF** (arXiv:2607.02383, 2026-07-03): RAG-based fact-checking systems generate "human-understandable justifications that explain how the retrieved evidence supports a verdict," and "professional fact-checkers report that such justifications enable audiences to scrutinise the reasoning process" — i.e., surfacing the verification chain (not just a verdict) is itself trust-relevant, not just accuracy-relevant.
- **Source Coverage and Citation Bias paper** (arXiv:2512.09483, 2025-12-11): uses two concrete third-party reliability datasets as ground truth for source scoring — "Media Bias/Fact Check (MBFC) for credibility and political bias, and VirusTotal for security and malicious-domain detection" — a reusable, off-the-shelf pattern for a source-reliability layer rather than inventing scoring heuristics from scratch.
- Secondary/lower-confidence source ("AI Trust Signals," authoritytech.io, 2026-07-20) claims "An arXiv study of 13 open-weight LLMs found that models prefer institutionally corroborated information (government and newspaper sources) over information from social media" — flagged as lower confidence since I could not independently pull the primary arXiv paper it cites within the time budget.

## (b) Counter-evidence / tensions found

- **Model-generation trend is not monotonically improving.** "Who Checks the Citations?" (arXiv:2606.21155, legal domain) found hallucination rates "no longer consistently decreasing across model generations" — GPT-5.1 hallucinated legal citations at 6.57% vs. 1.23% for an August-2024 GPT-4o release (p=0.001). Counters any assumption that "just use the newest model" fixes citation hallucination — newer/more agentic ≠ more reliable, and evaluation/verification tooling needs to be architecture-independent.
- **Confidence-signal quality is domain-dependent, not universal.** The clinical-tabular study (arXiv:2606.19509) found verbalized confidence "epistemically vacuous" (AUROC 0.50, i.e., worthless), while the open-QA training-free study (arXiv:2609.20541) found verbalized confidence to be the *best* training-free signal (AUROC ~0.94-0.96), beating self-consistency. These directly conflict on how much to trust a verbalized-confidence number — research-council should not assume verbalized confidence transfers cleanly from open QA-style claims to structured/technical claims, and should validate on its own claim types rather than assuming a universal result.
- **Self-consistency is a double-edged sword.** Multiple sources confirm self-consistency/majority-vote reduces some hallucinations, but arXiv:2609.20541 explicitly shows it "can amplify shared misconceptions" — unanimous agreement across samples occurred on 4/9 and 2/8 *wrong* answers in their tests. A council's Elo ranking / cross-model agreement should not treat "multiple hypotheses/agents agree" as strong evidence of correctness by itself, especially if all agents share the same base model or similar training data/blind spots.
- **AutoAIS/NLI-based excerpt-grounding checkers are themselves imperfect** (arXiv:2501.14883) — treating an automatic "does this excerpt support this claim" check as ground truth (rather than as a fallible judge with its own error rate) risks a false sense of security in an evidence-grounding pipeline.
- **Debate can make bias worse, not better** (arXiv:2505.19477) — directly cautions against research-council's "Reflection" objections + council debate design unless paired with position-swap controls and an independent meta-judge; naive multi-round debate before a verdict "amplifies biases sharply after the initial debate."
- Layered prompt-injection defenses reduce but do not eliminate attack success (best stacked defense in Hidden-in-Plain-Text still had 4.3–5.4% ASR under adaptive attacks) — there is no evidence in this research window of a fetch-and-verify pipeline that gets injection risk to zero; "don't execute instructions found in fetched content" needs to be an explicit, tested control, not assumed by default tool behavior.

## (c) Concrete upgrade ideas for research-council, tied to evidence

1. **[HIGH] Add a mandatory excerpt-support check per evidence record, using an NLI/AutoAIS-style verifier, but treat its verdict as fallible, not ground truth.** Basis: VeriScore's claim-verification stage (arXiv:2406.19276) and CiteEval (arXiv:2506.01829) show automatic support-checking is buildable and correlates well with human judgment (CiteEval: Pearson 0.731 statement-level); but arXiv:2501.14883 shows AutoAIS evaluators have real error rates, so the check should downgrade a claim to "unverified" on disagreement/low-confidence rather than "verified" on any pass. Concretely: for every claim→evidence link already required by research-council's design, run an automated "does this exact excerpt entail this claim" pass (even a cheap fine-tuned/small model per VeriFastScore, arXiv:2505.16973, which gets 9.9x speedup with near-equal quality) before a claim can be marked "verified."

2. **[HIGH] Require attribution to a *specific* source, not "supported by the evidence pool."** Basis: ProvenanceGuard (arXiv:2606.18037) shows source-blind verifiers wrongly pass claims attributed to the wrong document even when some other document in the pool does support them. Research-council's evidence records should enforce 1:1 claim→exact-excerpt→exact-source linkage (which the spec already implies) and the verifier must check *that specific pair*, never "is this claim supported by anything in the evidence set."

3. **[HIGH] Build disconfirmation search into the Reflection/Curiosity protocol as a structural step, not a prompted virtue.** Basis: "Failing to Falsify" (arXiv:2604.02485) shows LLMs default to confirmatory evidence search, but a rule-based intervention ("propose the opposite," "search for the negation") raised discovery rates from 42%→56%; the dual-perspective claim-verification paper (arXiv:2602.18693) shows retrieving on *both the claim and its explicit negation* gives +2–10% accuracy gains with no fine-tuning. Concretely: for every hypothesis/claim, the curiosity/reflection stage should generate and run at least one explicit negation-query search (e.g., "evidence against X," "X is false because," "contradicts X") as a required step, and evidence records should have a `stance: supports | contradicts | neutral` field so contradicting evidence is captured and surfaced in the report rather than only supporting evidence.

4. **[HIGH] Use a lexical/keyword-based retrieval pass specifically for contradiction-hunting, not just the primary semantic/relevance-ranked search.** Basis: TREC 2025 BioGen team (arXiv:2603.17580) found dense/semantic retrieval catastrophically fails to surface contradictions (MRR 0.023, "Semantic Collapse") because negation cues vanish in embedding space, while a BM25/lexical pipeline with negation-cue filtering achieved MRR 0.750. If research-council's evidence search is embedding/semantic-search-based (or relies on the underlying search tool's default relevance ranking), it should add explicit negation-keyword queries ("no evidence of," "contradicts," "failed to replicate," "disputed") as a parallel channel, not rely on the main relevance ranker to surface disagreement.

5. **[HIGH] Do not trust the model's self-reported confidence for hypothesis/claim confidence; derive it from measurable signals instead.** Basis: two studies directly conflict on verbalized confidence usefulness (arXiv:2606.19509 vacuous in one domain; arXiv:2609.20541 strong in another) — the safe design assumption is "unproven for our claim types." A cheap alternative with real evidence behind it: DINCO's distractor-normalization (arXiv:2509.25532, 10 calls beats 100-call self-consistency) or a cross-signal calibrator combining (a) number of independent supporting sources, (b) source reliability score, (c) whether a disconfirmation search was run and came back empty, into a single computed confidence rather than asking the model "how confident are you 0-100%."

6. **[MED-HIGH] Harden the blinded Elo Ranking step against LLM-as-judge failure modes with a Minimum Viable Validation Protocol.** Basis: arXiv:2606.19544's MVVP is directly reusable: (1) always swap/randomize the order of the two hypotheses being compared and check for position-bias flips, not just report a single pairwise verdict; (2) if using the same model family as a generation role to also judge, be aware self-preference bias is "structural, not a prompting mistake" (cited Panickssery et al. 2024 finding) — prefer a different model/role for judging than for generating, where feasible; (3) track whether "wins" are being driven by response length/verbosity and instruct the judge explicitly that length is neutral (standard, well-documented MT-Bench-era fix, reaffirmed by arXiv:2606.19544's low verbosity-bias-when-explicitly-controlled finding).

7. **[MED] If the council's Reflection stage involves multiple rounds of agents critiquing/debating hypotheses before Elo ranking, add an explicit meta-judge/aggregator layer rather than trusting the debate's final round.** Basis: EMNLP 2025 Findings (arXiv:2505.19477): "debate framework amplifies biases sharply after the initial debate... while meta-judge approaches exhibit greater resistance." Concretely, Meta-review should independently re-score post-debate outputs rather than simply averaging or taking the debate's self-reported consensus at face value.

8. **[MED] Add a source-reliability score to evidence records using off-the-shelf reliability datasets rather than ad hoc heuristics**, e.g., domain-level checks against something like Media Bias/Fact Check-style credibility lists for news/opinion sources, and flag primary (paper/preprint/official docs) vs. secondary (blog/aggregator) sources distinctly. Basis: arXiv:2512.09483 shows this is a standard, reusable pattern, and this session's own research repeatedly surfaced secondary "hub"/blog-style summarization sites (e.g., stabilarity.com, zandigital.in, exatoshi.uk) restating primary arXiv findings — sometimes with added unverifiable specifics (the stabilarity.com "10-model 2025 benchmark" page reads as plausible but its precision/thresholds are asserted without traceable methodology detail, versus the GhostCite/DRBench primary papers which specify exact procedures). Research-council should tag secondary "explainer" sites as lower-tier evidence and prefer the primary paper when both are found.

9. **[MED] Add a freshness/staleness field to evidence records and gate "current state of the art" or "as of" claims behind it.** Basis: Chronofy (2607.20560) and FRESCO (2604.14227) show retrieval systems routinely surface stale-but-relevant documents as if current, and "How Often Do Answers Change?" (2603.16544) shows LLMs are bad at self-judging which of their own claims are time-sensitive. Concretely: every evidence record should carry the source's publication/last-updated date (already implied by "exact excerpts" requirement) and any claim using time-sensitive language ("currently," "as of," "latest," "state of the art") should be required to cite the most recent evidence found and flag if a search for newer contradicting information was run.

10. **[MED] Treat fetched web page content as untrusted data with a pre-filter before it enters agent context, given research-council fetches arbitrary pages as its core evidence-gathering action.** Basis: IPI-proxy (2605.11868) explicitly names "MCP-mediated retrieval tools that never render a UI" as in-scope for indirect prompt injection risk — this is exactly research-council's Keenable-MCP fetch pattern. LivePI's Layer 1 (2605.17986) is a reusable design: run deterministic pattern-matching on fetched content for injection markers ("ignore previous instructions," "reveal system prompt," instructions impersonating a higher-authority role) before that content is added to context, and treat any instruction-like text found inside fetched content as data to quote, never as directives to follow (this is already stated as a rule in this task's own prompt — worth making it a structural, tool-level safeguard in research-council rather than a per-prompt reminder, since layered defenses cut ASR from ~23% to ~4% per Hidden-in-Plain-Text, 2026-01-22, but no single layer gets close to zero alone).

11. **[LOW-MED] Consider a lightweight per-claim self-consistency check only where cheap, and never treat unanimous multi-agent/multi-sample agreement alone as sufficient verification.** Basis: arXiv:2609.20541 shows self-consistency "can amplify shared misconceptions" (unanimous wrong answers occurred in a meaningful minority of error cases). If research-council's Generation stage produces multiple hypotheses from the same underlying model, agreement between them is weak evidence; the existing "no evidence = unverified" rule already covers this, but the report/FINDINGS.md should make explicit that model-model agreement is not itself evidence.

12. **[LOW] Track and periodically re-validate any LLM-judge role against a small human-labeled calibration set, and treat judge "drift" as an operational risk to monitor, not a solved problem.** Basis: arXiv:2606.19544 explicitly flags that hosted judge models "are known to drift across provider-side updates, sometimes silently." For a plugin meant to be reused over time, this argues for keeping a small fixed regression set of past council decisions to spot-check the Elo/Meta-review roles periodically.

## (d) Open questions

- No primary source in this session directly measured hallucination/verification specifically for a "council of roles + blinded Elo ranking" architecture like research-council's — the LLM-as-judge findings (pairwise, position bias, debate amplification) generalize from single-response grading/preference literature; whether they transfer identically to ranking *hypotheses* (rather than model responses) is untested and worth research-council's own internal eval.
- The "AI Trust Signals" claim about institutional-source preference (13 open-weight LLMs) could not be traced to its primary arXiv paper within the time budget — flagged as unverified/low-confidence, should not be relied on without finding the primary source.
- No source in this session gave a validated, general-purpose numeric formula for source-reliability scoring beyond "use an existing third-party dataset (MBFC, VirusTotal) where the domain is covered" — for domains outside news/security (e.g., academic preprints, vendor docs, company blogs) no equivalent off-the-shelf reliability score was found; this is a gap research-council would need to fill with its own heuristic (e.g., peer-reviewed > preprint > vendor blog > uncorroborated blog) rather than sourced evidence.
- Whether DINCO-style distractor-normalization or cross-model calibrators (arXiv:2606.19509) are practical inside a prompt-only, no-fine-tuning plugin architecture (as opposed to a research lab setting with model access) is untested — these techniques need adaptation (e.g., "generate 2-3 plausible alternative claims and ask the model to rate confidence in each independently, then normalize") that this session did not find validated at the prompt-engineering level specifically.
- Freshness/staleness tooling (Chronofy, FreshCache, FRESCO) is aimed at RAG systems with their own indexed corpora and re-fetch policies; how this maps to a session-bounded, budget-capped research agent that does one-shot web fetches (rather than maintaining a persistent index) is an open design question — the useful takeaway (capture and use publish/fetch dates, flag time-sensitive language) is transferable, but the caching/re-fetch-policy machinery in these papers is not directly applicable.
